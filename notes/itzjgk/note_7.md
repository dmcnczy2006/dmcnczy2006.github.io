## 7.1 数据库的搭建

**注意：高考对与数据库相关的 Python 编程涉及较少。** 这篇笔记仍完整地介绍和补充课本中的“数据库搭建”内容，主要供大家在搭建信息系统的实践中参阅；同时给基础较好的同学一定的补充，从而使他们更从容地解答模拟考中的相关问题。**高考复习时，可以跳过这一部分**，只需记住 **`sqlite3` 中操作数据库的 Python 函数的调用顺序**即可。

### 7.1.1 使用 SQL 操作数据库 <span style="font-size: smaller;">模拟考</span>

现在可以在脑海中迅速地过一遍 Excel 软件的操作。我们知道，一个 Excel 工作簿文件内含多个工作表，每个工作表都可以执行“**增删改查**”等操作。

现在想象：一个程序员在操作 Excel 时丢失了鼠标，而且无法通过任何方式选中工作表中的内容。此时，这位程序员只能通过**写入计算机能听懂的命令**对数据表进行“增删改查”操作。

我们接下来要处理的**数据库**和 Excel 类似，都是用来存储和管理数据的工具，一个数据库文件（后缀名往往是 `.db`）也包含了**多个二维的、结构化的数据表**。而面对数据库，我们就是那个倒霉的程序员。我们只能通过写入计算机能听懂的命令对数据表进行"增删改查"操作。

这种命令就是 **SQL（结构化查询语言）**，它是专门用来操作数据库的编程语言。通过 SQL 语言，我们可以精确地控制数据库中的每一个操作。


```sql
-- 创建带智能校验的用户表
CREATE TABLE IF NOT EXISTS users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- 自增ID（自动生成唯一编号）
    username TEXT NOT NULL UNIQUE,         -- 用户名：必填且不可重复
    password TEXT NOT NULL,                -- 密码（可以加密存储）
    created_time DATETIME DEFAULT CURRENT_TIMESTAMP  -- 创建时间：自动打时间戳
);
```

### 7.1.2 将 SQLite 写进服务器 Python 程序中

信息系统框图中，读取和写入数据库是由**服务器**来执行的。所以，数据库的搭建程序应该写在服务器中，和提供网络服务的程序写在一起。

我们使用 Python 内置的 `sqlite3` 标准库实现用 Python 搭建并控制信息系统中的数据库。**`sqlite3` 中操作数据库的 Python 函数的调用顺序在考试中尤为重要**。

```python
import sqlite3

# 连接数据库（若不存在则自动创建）
conn = sqlite3.connect('example.db')
cursor = conn.cursor()

# 创建表（若不存在）
cursor.execute('''CREATE TABLE IF NOT EXISTS users 
                  (id INTEGER PRIMARY KEY, name TEXT, age INTEGER)''')

# 插入数据（参数化查询防止SQL注入）
cursor.execute("INSERT INTO users (name, age) VALUES (?, ?)", ("Alice", 25))
conn.commit()  # 提交事务，否则数据不会持久化

# 查询数据
cursor.execute("SELECT * FROM users WHERE age > ?", (20,))
print(cursor.fetchall())  # 输出：[ (1, 'Alice', 25) ]

# 关闭连接
conn.close()
```

## 7.2 智能终端的搭建

智能终端是信息系统中集成了计算、通信、感知与控制等功能的智能化设备。教材中使用 micro:bit 作为智能终端的示例，在其中编写的 Python 程序反映了 micro:bit 的工作逻辑。但实际上，智能终端的种类有很多，不仅限于 micro:bit。任何设备只要**具备以下三个功能**，就可以被视为符合考试要求的智能终端：

1. 具备网络通信功能，能与服务器进行数据交换；
2. 能与现实环境进行交互（例如：测量环境温度、控制 LED 灯的开关等）；
3. 支持运行 Python 程序，并且可以通过 Python 程序直接或间接地实现上述两项功能。

高考题目不会指定具体用哪个品牌的智能终端，但出现的智能终端**一定都符合这些基本原理**。智能终端的核心功能通过 Python 程序实现，其编程逻辑需结合硬件特性与软件控制。下面从硬件交互、网络通信、程序结构三个层面展开说明。其中， **“程序结构”部分作为重要考点，需要熟练掌握**。

### 7.2.1 Python 与硬件交互

智能终端的物理接口通过 Python 库实现控制，典型操作包括：

**1. 传感器数据读取**  

```python
# 以温度传感器为例（不同硬件需调整库名称）
from machine import Pin, ADC
temp_sensor = ADC(Pin(26))  # 假设传感器连接至26号引脚
raw_value = temp_sensor.read_u16()
temperature = (raw_value / 65535) * 330  # 模拟值转实际温度
```

**2. 执行器控制**  

```python
# 控制LED灯开关（GPIO输出模式）
led = Pin(15, Pin.OUT)
led.value(1)  # 高电平点亮
led.value(0)  # 低电平熄灭
```

### 7.2.2 网络通信实现

智能终端通过 Python 标准库或第三方库与服务器交互，常见方式包括：

### 7.2.3 程序逻辑设计

为了让智能终端程序满足实时性要求，通常在智能终端程序中使用不断重复执行的**主循环**（通过 `while True` 实现）。

**主循环框架示例**：一个智能终端若能实现重复采集环境温度、自动开关风扇的功能，那么写在其中的 Python 代码框架如下：

```python
import time

while True:
    # 1. 采集环境数据，具体实现采集的代码略去
    temp = read_temperature()
    
    # 2. 数据处理与判断
    if temp > 30:
        control_fan(True)   # 打开风扇，具体实现略去
    if temp < 20:
        control_fan(False)  # 关闭风扇，具体实现略去
    
    # 3. 定时上传数据，具体实现上传的代码略去
    if time.time() % 60 == 0:  # 每分钟上传
        send_to_server(temp)
    
    time.sleep(0.1)  # 等待 0.1 秒
```

具体的数据采集办法，以及与服务器的信息交换和与现实世界的交互方式不是笔试中要求的重点。考试往往对主循环的**逻辑**进行设问考察。主循环的逻辑往往**在题干中被鲜明地呈现**。做逻辑相关的代码填空时，只需要将题干中的**现实语言转换成 Python 代码**即可。
  
> 【例题】 小明在实验室搭建一套花园智能灌溉系统，分成若干个分区，每个分区灌溉阀门都能独立控制。当阀门关闭时，若传感器检测到土壤水分值持续 20 分钟低于 10，则打开阀门；当阀门打开时，若土壤水分值高于 40，或阀门持续 30 分钟处于打开状态，则关闭阀门。
>
>（1）若分区 1 在某时刻的水分值为 11，阀门状态是关闭的，18 分钟后测得水分值为 9，此时阀门状态为（单选，填字母：A.打开 / B.关闭）
> 
> （2）实现上述功能的部分 Python 程序如下，请在划线处填入合适的代码。
> 
> 
> ```python
> n = 5                   # 假设花园有 5 个分区
> a = [0] * n             # 各分区土壤水分值
> b = [0] * n             # 各分区灌溉阀门状态，0 表示关闭，1 表示打开
> t = [0] * n             # 计时器，记录持续时间
> mmin, mmax = 10, 40     # 设置土壤水分值范围
> 
> while True:
>     # 从传感器获取各分区土壤水分值，保存在 a 中，代码略
>     for i in range(n):
>         if ________:    # ①
>             if a[i] < mmin:
>                 t[i] += 1
>             else:
>                 t[i] = 0
>             if t[i] >= 20:
>                 ________    # ②
>                 b[i] = 1
>         else:
>             ________        # ③
>             if a[i] > mmax or t[i] >= 30:
>                 t[i] = 0
>                 b[i] = 0
>     # 延时 1 分钟，根据列表 b 的值，更新阀门状态，代码略
> ```
> 
> **（1）阀门状态判断**
> 
>   - **答案**：B（关闭）
> 
>   - **解析**：
> 
>       - 当分区 1 的阀门关闭时，初始土壤水分值为 11，高于设定的阈值 10，此时计时> 器`t[i]`为 0。
> 
>       - 18 分钟后测得水分值为 9，虽然低于阈值 10，但系统需要检测到土壤水分值持> 续 20 分钟低于 10 才会打开阀门。
> 
>       - 由于只持续了 18 分钟（未达到 20 分钟的要求），因此阀门保持关闭状态。
> 
> 
> **（2）Python 程序填空**
> 
>   - **答案**：
> 
>       - ①`b[i] == 0`
> 
>       - ②`t[i] = 0`
> 
>       - ③`t[i] += 1`
> 
>   - **解析**：根据题干，程序逻辑分为两种情况：
>   1. 当阀门关闭（`b[i] == 0`）时：
> 
>       • 如果土壤水分值低于阈值（`a[i] < mmin`），计时器加 1（`t[i] += 1`）。
> 
>       • 如果土壤水分值高于或等于阈值，计时器重置为 0（`t[i] = 0`）。
> 
>       • 当计时器达到 20 分钟（`t[i] >= 20`），打开阀门（`b[i] = 1`），并重置计> 时器（`t[i] = 0`）。
>
>   2. 当阀门打开（`b[i] == 1`）时：
> 
>       • 每次循环（每分钟）计时器加 1（`t[i] += 1`），记录阀门打开时间。
> 
>       • 如果土壤水分值高于最大阈值（`a[i] > mmax`）或计时器达到 30 分钟（`t[i] > >= 30`），关闭阀门（`b[i] = 0`），并重置计时器（`t[i] = 0`）。
>

**注意事项**  
1. 硬件差异性处理：不同设备需替换对应的硬件驱动库（如 micro:bit 使用 `microbit` 库，树莓派使用 `RPi.GPIO`）  
2. 资源优化：嵌入式设备内存有限，应避免复杂数据结构  
3. 异常处理：必须包含网络重连、传感器失效等容错机制  
4. 异步编程：部分场景需使用 `asyncio` 库实现非阻塞操作  

通过以上编程模式，智能终端即可实现"感知-计算-控制-通信"的完整闭环，满足信息系统对终端设备的功能需求。
